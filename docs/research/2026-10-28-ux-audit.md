# The whole window, read as a daily tool

> UI/UX audit, 2026-10-28 (#746). Sources are the code on `develop` at
> `c1f3ca0`, read surface by surface with each claim checked at its
> `file:line`, and the public documentation of the tools named under
> "Prior art". Analysis only: the M18 section of `docs/ROADMAP.md` makes the
> decisions, and every gap below is an issue labelled `M18`.

## Why this pass, after M15

M15 (#420) audited the **review column**. Four faces built in four
milestones got one cursor, one glyph vocabulary, chrome that names the face,
zoom, and help derived from the key tables. It deliberately left alone the
rest of the window: the sidebar, the session pane, the leader, how omatty
reports what it did, and each face's depth once you are reading in it.

This pass reads the whole window the way an operator meets it in a day:
start omatty, watch several sessions, read a turn's diff, comment, gate,
check the tracker, ship. It asks one question of each step: does the tool do
what a person who already uses lazygit, tmux, delta or gh-dash expects, and if
not, is the difference argued or accidental?

**Method.** Two read-only surveys of `internal/tui/{app,keys,theme}` and
the domain they draw, followed by a verification pass that re-read every
cited line. Two survey claims did not survive it and are corrected below,
and one was dropped. Prior art was taken from each tool's own docs, linked
inline.

**Already tracked, so not re-filed:** #737, the working spinner that keeps
turning after an interrupt or a `/compact`. The surveys traced the same
cause: no hook marks an interrupted turn ended, and `parseUser` reads
`[Request interrupted by user]` as a new prompt
(`internal/service/status/transcript.go:57-79`).

## 1. The finding that outranks the rest

**omatty's default leader takes Claude Code's own `Ctrl+O`.** Claude Code
binds `Ctrl+O` to its transcript viewer: tool calls in full, MCP calls
expanded, per-message timestamps ([interactive
mode](https://code.claude.com/docs/en/interactive-mode)). `keys.Router.Next`
(`internal/tui/keys/router.go:64-77`) swallows the leader and gives the next
key to omatty with no exception, so `ctrl+o ctrl+o` is dropped. Inside omatty,
with the default config, the most detailed view of a turn that Claude
offers cannot be opened. In a product whose claim is judging turns, that is
the wrong thing to make unreachable.

Every multiplexer solved this the same way. tmux's `send-prefix` sends the
prefix through when it is pressed twice; screen does the same with `C-a a`;
zellij has a binding that sends the literal prefix and a locked mode. zellij
hit this exact conflict with Claude Code's `Ctrl+B`. The fix stays inside
invariant 1, because the route is decided by modal state (leader pending, key
is the leader), not by inspecting what the agent might want. **#747.**

## 10. What this pass does not propose

- **Resizable splits by drag.** M15 chose zoom over a persisted split
  width, and #754 and #755 are the smaller answer.
- **User colour themes.** #760 is one palette on two grounds.
- **A command palette.** The leader plus help with `/` (#438) covers it,
  and a second way to run every command doubles what help has to say.
- **Writing to the forge from the tracker** beyond #331.
